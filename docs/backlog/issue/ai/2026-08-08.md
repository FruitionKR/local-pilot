# AI(llmPipeline) 이슈 — 2026-08-08

## Spring 소유 Skill의 AI 생성·검토·실행 계약

### 배경

Skill과 version의 권위 저장소를 Spring Backend로 확정했다. Spring은 사용자·Workspace 권한,
목록·상세·version, command 중복, 자동 라우팅 상태, soft delete와 게시 transaction을 관리한다.
llmPipeline은 Skill을 저장하거나 Spring DB를 직접 조회하지 않고 AI 구체화·보안 검사와 Agent 실행만
담당해야 한다.

현재 계약은 `docs/spec/llmpipeline-backend-api-contract.md`의 다음 위치를 기준으로 재정의가 필요하다.

- `Agent Skill — Spring 구현 방식 결정 필요`
- `안전성 미리보기 — POST /skills/preview`
- `Markdown Agent — POST /agent/turn`

Backend 연결 위치:

- `backend/src/main/java/fruition/skill/repository/PipelineSkillRequester.java`
- `backend/src/main/java/fruition/agent/repository/PipelineAgentRequester.java`

### 1. 자유 입력·참조 문서 기반 초안 생성

- 신규 endpoint: `POST /skills/refine`
- 사용자 입력 `command`, `name`, `instructions_markdown`, `scope_type`과 Spring이 검증한
  `reference_documents`를 받는다.
- 사용자가 입력한 `name`과 비어 있지 않은 `command`는 유지한다.
- 비어 있는 command, description, 구체화한 instructions, capabilities, allowed_tools를 생성한다.
- 응답은 저장하지 않은 초안이며 `persisted=false`다.
- 참조 문서는 `id`, `name`, `content_hash`, `content`를 받는다.
- llmPipeline DB에는 Skill이나 초안을 저장하지 않는다.

### 2. 규칙 검사와 LLM 의미 검사

- 기존 `POST /skills/preview`를 영속화 없는 검사 endpoint로 유지·확장한다.
- 기존 규칙 검사에 LLM 의미 검사를 추가한다.
- 응답에는 완성된 `draft`, 검사별 `checks`, `publish_allowed`를 포함한다.
- 차단, LLM timeout, provider 오류, schema 오류는 모두 fail-closed로 반환한다.
- llmPipeline은 `review_token`을 발급하거나 Skill을 게시하지 않는다.
- Spring이 검사 결과와 정규화 definition hash를 사용해 `review_token`을 발급·검증한다.

### 3. Spring 전달 Skill을 사용하는 Agent 실행

- llmPipeline의 Agent 실행은 자체 Skill repository 대신 Spring이 `/agent/turn` 요청에 전달한 Skill
  후보와 version definition을 사용한다.
- 자연어 자동 선택 요청에는 `auto_routing_enabled=true`인 접근 가능한 후보만 전달된다.
- `/command` 직접 실행에는 Spring이 command로 확정한 Skill 하나와 실행할 version을 전달한다.
- 전달할 Skill definition은 최소한 다음 필드를 포함한다.
  - `skill_id`
  - `version_id`
  - `name`
  - `description`
  - `instructions_markdown`
  - `capabilities`
  - `allowed_tools`
- llmPipeline은 전달받은 `allowed_tools`와 capability 정책을 다시 검증한다.
- AgentRun은 시작 시 전달된 `skill_id`, `version_id`, definition snapshot을 사용한다. 실행 도중 Spring에서
  Skill이 수정되거나 삭제돼도 이미 시작한 실행은 같은 snapshot으로 완료한다.

### 4. 기존 llmPipeline Skill 영속화 경로 정리

- Spring 신규 기능은 llmPipeline의 `POST /skills`, `PATCH /skills/{skill_id}`,
  `POST /skills/{skill_id}/publish`, 목록·상세·enable·disable API를 사용하지 않는다.
- 기존 route와 PostgreSQL repository의 제거 여부는 호환 호출자를 확인한 뒤 별도 결정한다.
- 신규 Agent 실행 경로는 llmPipeline Skill DB가 없어도 동작해야 한다.
- `AGENT_SKILLS_ENABLED`와 내부 token의 역할을 Spring 전달 Skill 계약에 맞춰 갱신한다.

### 완료 조건

- [ ] 자유 입력·참조 문서 기반 AI 구체화 route와 schema 테스트가 통과한다.
- [ ] AI 결과가 사용자 이름과 직접 입력한 command를 보존한다.
- [ ] 규칙 검사와 LLM 의미 검사 실패가 fail-closed로 처리된다.
- [ ] 검사 endpoint가 Skill·초안·token을 저장하거나 발급하지 않는다.
- [ ] `/agent/turn`이 Spring 전달 후보로 자연어 Skill을 선택한다.
- [ ] `/agent/turn`이 Spring이 확정한 `/command` Skill을 명시적으로 실행한다.
- [ ] 자동 라우팅 OFF Skill은 자연어 후보에서 제외되지만 명시적 실행은 가능하다.
- [ ] 전달 definition의 capability·allowed tool 정책 위반이 거부된다.
- [ ] 실행 중 Skill 수정·삭제가 시작된 AgentRun snapshot을 변경하지 않는다.
- [ ] 신규 Agent 경로가 llmPipeline Skill DB 조회 없이 동작한다.
- [ ] `docs/spec/llmpipeline-backend-api-contract.md`에 변경 계약을 반영한다.
- [ ] Spring Backend와 실제 E2E 호출을 검증한다.
