# AI(llmPipeline) 이슈 — 2026-08-08

## Skill 생성 화면 연동을 위한 llmPipeline 계약 확장

### 배경

Spring Backend에 Skill 생성 화면용 공개 API와 llmPipeline requester를 추가했다. 현재 구현된
llmPipeline 계약 중 `POST /skills/preview`의 규칙 검사는 재사용하지만, 합의한 자유 입력 기반 AI
구체화와 검토된 초안의 원자적 게시를 지원하려면 내부 API 확장이 필요하다.

현재 계약은 `docs/spec/llmpipeline-backend-api-contract.md`의 다음 위치를 기준으로 한다.

- `Agent Skill — Spring 구현 방식 결정 필요`
- `완료된 Agent Run에서 초안 제안 — POST /skills/draft-from-runs/preview`
- `안전성 미리보기 — POST /skills/preview`
- `Skill 생성 — POST /skills`
- `Publish — POST /skills/{skill_id}/publish`

Backend 연결 위치:

- `backend/src/main/java/fruition/skill/repository/PipelineSkillRequester.java`
- 공개 API: `POST /api/workspaces/{workspace_id}/skills/refine`
- 공개 API: `POST /api/workspaces/{workspace_id}/skills/reviews`
- 공개 API: `POST /api/workspaces/{workspace_id}/skills`

### 1. 자유 입력·참조 문서 기반 초안 생성

- 신규 endpoint: `POST /skills/refine`
- 사용자 입력 `command`, `name`, `instructions_markdown`, `scope_type`과 Spring이 검증한
  `reference_documents`를 받는다.
- 사용자가 입력한 `name`과 비어 있지 않은 `command`는 유지한다.
- 비어 있는 command, description, 구체화한 instructions, capabilities, allowed_tools를 생성한다.
- 응답은 저장하지 않은 초안이며 `persisted=false`다.
- 참조 문서는 `id`, `name`, `content_hash`, `content`를 받는다.

### 2. 기존 안전성 preview 확장

- 기존 endpoint: `POST /skills/preview`
- 기존 규칙 검사를 유지하고 LLM 의미 검사를 추가한다.
- 자유 입력 상태라 definition 필드가 비어 있으면 검사 전에 초안을 완성한다.
- 규칙 검사와 LLM 의미 검사가 모두 통과할 때만 10분 유효 `review_token`을 반환한다.
- token은 Workspace, 사용자, 전체 Skill definition, scope, 참조 문서 ID·content hash를 포함한
  정규화 hash에 서명한다.
- 차단, LLM timeout, provider 오류, schema 오류에는 token을 발급하지 않는다.
- 응답에는 완성된 `draft`, 검사별 `checks`, `publish_allowed`, `review_token`, `expires_at`을 포함한다.

### 3. 검토된 신규 Skill의 원자적 게시

- 신규 endpoint: `POST /skills/publish-reviewed`
- `review_token`, 검토된 전체 definition, 참조 문서 snapshot을 받는다.
- token 서명·만료와 최종 요청 hash를 검증한다.
- `workspace_id + command` 동시 게시를 직렬화하고 scope별 command 중복을 재검사한다.
- 하나의 DB transaction에서 Skill을 생성하고 version 1을 `published`, Skill을 `enabled`로 만든다.
- 실패하면 전체 rollback하여 비활성 draft를 남기지 않는다.
- 기존 `POST /skills`, `POST /skills/{skill_id}/publish`는 저장형 draft와 기존 Skill version 게시용으로 유지한다.

### 완료 조건

- [ ] 신규·확장 endpoint의 Pydantic schema와 route 테스트가 통과한다.
- [ ] AI 구체화 결과가 사용자 이름과 직접 입력한 command를 보존한다.
- [ ] 규칙 검사와 LLM 의미 검사 실패가 fail-closed로 처리된다.
- [ ] 초안·참조 문서 변경, token 위조·만료가 게시를 차단한다.
- [ ] 동시 command 게시 중 하나만 성공한다.
- [ ] 게시 transaction 실패 시 Skill 또는 version 일부가 남지 않는다.
- [ ] `docs/spec/llmpipeline-backend-api-contract.md`에 신규 계약을 반영한다.
- [ ] Spring Backend와 실제 E2E 호출을 검증한다.
