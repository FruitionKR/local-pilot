### 레거시 /original 계약 결정 — A안(변경 없음)

- `GET /documents/{id}/original`은 "업로드 원본 전용"으로 유지하기로 결정했다. 직접 생성 문서(`source_uri=null`)는 계속 `404 DOCUMENT_ORIGINAL_NOT_FOUND`를 반환하고, 최신 편집본은 `/export`·`/content`가 담당한다.
- 근거: 프론트의 모든 노트 생성이 업로드 경로라 `source_uri`가 항상 존재해 404가 실제로 발생하지 않음. fallback 추가는 소비자 없는 speculative 코드. 코드 변경 없음.
- 원 이슈: `docs/issue/backend/2026-07-25.md`, `docs/issue/backend/2026-07-26.md`의 `9.`.

### 편집본 재ingest API (POST /documents/{id}/ingest) — 이슈 4의 1단계

- 편집 가능 Markdown 문서의 DB 편집본을 MinIO 원본으로 승격한 뒤 Wiki 파이프라인에 재처리하는 `POST /api/workspaces/{workspace_id}/documents/{document_id}/ingest`를 추가했다. 업로드 당시 원본이 아닌 편집한 내용으로 위키를 다시 만들 수 있다.
- 이미 `processing`이면 `409 DOCUMENT_ALREADY_PROCESSING` 거절. 업로드 자동 처리는 유지(additive).
- 완전한 업로드/ingest 분리(업로드는 `uploaded`만 + 프론트 ingest 버튼)는 `docs/issue/backend/2026-07-26.md`의 `4.` 2단계로 남김.
- 요약: `docs/changelog/backend.md` 2026-07-26 항목.
