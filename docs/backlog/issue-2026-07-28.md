## Frontend·Backend — AI 편집 스냅샷과 채팅 문서 편입 저장 연결

### 해결 내용

- Frontend가 AI 편집 결과 적용 시
  `PUT /api/workspaces/{workspace_id}/documents/{document_id}/content`에
  `source=agent`를 보내고 즉시 저장한다.
- Backend는 해당 저장을 `document_content_versions`에 영속화한다. 일반 자동 저장은
  `source`를 생략하므로 스냅샷을 추가하지 않는다.
- 채팅 문서 편입 성공 후 Frontend는 `exportDocumentId`를 보관하고 문서 목록을 새로 불러온 뒤
  저장된 문서를 자동으로 연다.
- Backend의 평면 목록, 폴더 트리, 이름 검색은 `origin='chat_export'` 문서를 포함한다.
  따라서 MinIO와 `documents` 테이블에 생성된 편입 Markdown이 워크스페이스 문서로 노출된다.

## AI/Pipeline — Wiki 페이지 이름 변경과 응답 개인 설정

### 해결 내용

- `PATCH /wiki/pages/{wiki_page_id}/rename`으로 title만 바꾸거나 title과 slug를
  같은 PostgreSQL transaction 안에서 변경할 수 있게 했다.
- Query와 Agent turn 요청에 optional `output_language`, `response_length`,
  `allow_web_search` 필드를 추가했다.
- 언어·분량 enum을 trusted system 규칙으로 변환해 내부 Wiki 답변과 web fallback에
  동일하게 적용하고, 필드가 없으면 기존 prompt를 그대로 유지한다.
- Agent 채팅은 Query와 같은 선호도 경로를 사용한다. Markdown 편집에는 언어 선호도를
  전달하지 않고, 새 문서 생성은 사용자 지시 언어를 우선한 뒤 선호 언어를 적용한다.
- `allow_web_search=false`이면 점수 기반 fallback과 evaluator의 web route 가능 여부를
  모두 차단한다. `true`여도 `QUERY_WEB_SEARCH_MODE`가 비활성화돼 web search port가
  없으면 검색하지 않는다.

### 검증

- 지원 enum과 잘못된 enum, 설정 누락 시 기존 prompt 유지, Query·Agent 전달,
  새 문서 생성 언어 규칙을 검증했다.
- 내부 근거 부족 상태에서 `allow_web_search=false`이면 web search port가 호출되지
  않고 evaluator에도 검색 불가로 전달되는지 확인했다.
- llmPipeline 전체 테스트 `809 passed, 61 subtests passed`로 검증했다.
