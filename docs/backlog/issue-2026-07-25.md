## Backend — wiki-schema Java 프록시

### 해결 내용

- llmPipeline `wiki_schema` 모듈을 workspace 범위 public API로 중계하는 Spring 프록시를 추가했다.
- endpoint 4개를 `AgentTurnController`/`PipelineAgentRequester` 패턴 그대로 구현했다.
  - `POST /api/workspaces/{workspace_id}/wiki-schema/preview` → llmPipeline `POST /wiki-schema/preview`
  - `POST …/wiki-schema/drafts` → llmPipeline `POST /wiki-schema/drafts` (`workspace_id`는 path, `user_id`는 `@AuthenticationPrincipal`에서 주입)
  - `POST …/wiki-schema/{schema_id}/activate` → llmPipeline `POST /wiki-schema/{schema_id}/activate`
  - `GET …/wiki-schema/active` → llmPipeline `GET /wiki-schema/active?workspace_id&user_id` (활성 스키마가 없으면 `null` 그대로 반환)
- workspace 멤버십을 검증하고 비멤버는 `WorkspaceNotFoundException`(404)으로 차단한다.
- 오류 매핑은 `PipelineWikiSchemaException`/`GlobalExceptionHandler`로 처리한다. pipeline의 400/422/404는 원본 detail을 보존하고, 그 외는 503(`WIKI_SCHEMA_PIPELINE_UNAVAILABLE`)으로 변환한다.
- pipeline base URL 설정 `app.wiki-schema.endpoint`(`WIKI_SCHEMA_ENDPOINT`)와 timeout을 추가했다.

### 검증

- requester(snake_case 변환·null name 생략·활성 없음 시 `null` 통과·422/404 body 보존·500→503), service(멤버십·위임·비멤버 차단), controller(4개 endpoint·미인증 401·blank 입력 400) 테스트를 추가했다.
- `./gradlew test` 전체가 통과했다.

## Backend — wiki maintenance lint 프록시

### 해결 내용

- llmPipeline `POST /wiki/maintenance/lint`를 workspace 범위 public API로 중계하는 Spring 프록시(`fruition.wikimaintenance`)를 추가했다.
- `POST /api/workspaces/{workspace_id}/wiki/maintenance/lint`에서 `workspace_id`를 path, `user_id`를 `@AuthenticationPrincipal`에서 주입한다.
- public body는 `{ materializePromotions, dryRun }`만 받고(둘 다 optional), LLM provider·model 등 pipeline 튜닝 knob은 노출하지 않고 pipeline 기본값을 사용한다.
- body를 생략하거나 옵션이 null이면 payload에서 생략해 pipeline 기본값(`dry_run=true`, `materialize_promotions=false`)이 적용된다.
- workspace 멤버십을 검증해 비멤버 요청을 `WorkspaceNotFoundException`(404)으로 차단한다.
- 오류 매핑은 `PipelineWikiMaintenanceException`/`GlobalExceptionHandler`로 처리한다. pipeline의 400/422는 원본 detail을 보존하고, 그 외(500 포함)는 503(`WIKI_MAINTENANCE_PIPELINE_UNAVAILABLE`)으로 변환한다.
- lint가 LLM을 호출하므로 프록시 read timeout 기본값을 200초로 두고 `app.wiki-maintenance.endpoint`(`WIKI_MAINTENANCE_ENDPOINT`)를 추가했다.

### 검증

- requester(user_id·workspace_id 주입, null 옵션·null 요청 시 payload 생략, 400 body 보존, 500→503), service(멤버십·위임·비멤버 차단), controller(body 있음·없음·미인증 401) 테스트를 추가했다.
- `./gradlew test` 전체가 통과했다.

### 확인 위치
