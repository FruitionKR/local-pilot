# 2026-07-15 Backend 이슈 — 해결 항목 기록

## 1. query evidence source_refs 노출 (해결)

- **배경**: llmPipeline은 evidence마다 다중 문서 `source_refs`를 보냈으나, backend `PipelineQueryResponse.EvidenceSnippet`에 필드가 없어 Jackson 역직렬화 단계에서 버려졌다. 하나의 rank가 대표 문서 외 다른 문서 block을 참조하면 두 번째 이후 문서 근거가 저장·노출되지 않았다.
- **조치**: `EvidenceSnippet`에 `source_refs`(`[{source_document_id, source_block_id}]`) + 중첩 `SourceRef` 추가, `ChatMessageReference` 도메인·응답 DTO에 `source_refs` 추가, `QueryService` 저장·`ChatSessionController` 조회 매핑 연결, `chat_message_references.source_refs` 컬럼(Flyway `V7`). legacy `source_document_id`/`source_block_ids` 유지(additive).
- **검증**: query·chat 74개 테스트 + 전체 컨텍스트 로딩(`V7` 적용 + `ddl-auto=validate`) 통과. `PipelineQueryResponseTest`에 source_refs 역직렬화, `QueryServiceTest`에 다중 문서 근거 보존 검증 추가.
- **변경 기록**: `docs/changelog/backend.md` 2026-07-21 항목. **계약**: `docs/spec/api/query.md`, `docs/spec/api/chat.md`.
- **후속(프론트 소비)**: `docs/issue/frontend/2026-07-15.md` #7.

## 2. documents/wiki_pages FK CASCADE + migration 도구 (해결)

- **배경**: `workspace_id` FK CASCADE가 chat_sessions만 적용됐고, documents/wiki_pages는 애플리케이션 레벨 삭제 유지 + Flyway 미도입 상태였다.
- **조치**: Flyway 마이그레이션 도구 도입(스키마 단일 소스화, `ddl-auto=validate`). `V3__add_workspace_fk_cascade.sql`이 documents·wiki_pages·chat_sessions에 `ON DELETE CASCADE` 적용(workspace 삭제 시 concept page 고아 버그 해소 포함). `V2`가 잔재 unique constraint 제거.
- **참고**: `WorkspaceService.delete`의 앱 레벨 `deleteAllByWorkspaceId`는 이제 DB CASCADE와 중복이나 버그는 아니다(선택적 정리 대상).
- **상세**: `docs/backlog/issue-2026-07-03.md` FK CASCADE 섹션, ADR `docs/spec/pipeline-db-ownership.md`. Flyway 도입 경위는 `docs/backlog/issue-2026-07-16.md`.
