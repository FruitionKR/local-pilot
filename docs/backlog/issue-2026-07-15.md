## 1. pipeline run 동시 실행 방지

- 여러 문서 동시 업로드 시 DB 큐(PR 55)는 도입됐으나 worker가 POST 직후 큐 항목을 삭제해 pipeline run 동시 실행이 여전히 가능.
- 해결: cached `RunPipelineUseCase`에 process-wide `threading.Lock`을 적용해 일반 문서와 Chat Wiki run을 직렬화했다.
- 검증: `llmPipeline/tests/modules/wiki_ingestion/test_run_pipeline.py`, `test_execute_serializes_concurrent_pipeline_runs`
- 상세: `docs/backlog/issue-2026-06-29.md` 이슈 1, `docs/backlog/issue-2026-06-26.md` 동시 업로드 처리 순서.

## 2. pipeline run heartbeat

- `pipeline_runs`에 `updated_at` 없음, `touch_pipeline_run` 미구현. backend 측 수신부(`applyPipelineEvent`, `markProcessingHeartbeat`)는 구현 완료 — 송신부만 남음.
- 해결: Flyway V6로 `updated_at`을 추가하고 `PipelineLog.emit()`의 progress callback을 `touch_pipeline_run(run_id)`에 연결했다.
- 실패 정책: heartbeat DB 갱신 실패는 pipeline을 중단하지 않고 `pipeline.log`에 기록한다.
- 검증: `llmPipeline/tests/modules/wiki_generation/test_pipeline_log.py`, `llmPipeline/tests/modules/wiki_ingestion/test_pipeline_run_heartbeat.py`
- 상세: `docs/backlog/issue-2026-06-26.md` llmPipeline heartbeat, `docs/backlog/issue-2026-06-29.md` 참조 절.

## 3. Markdown 편집 router와 생성 계약 보강

- 일반 `whole_document` 편집과 원문 구조 보존형 cleanup을 template 재구성으로 오분류하던 로컬 guard와 router prompt를 수정한다.
- `insert_after`를 `current_section` 전용 operation으로 추가하고, 현재 섹션 target이 없으면 `clarify`로 반환한다.
- `markdown_create`의 `title`, `summary`, `markdown` 필수 필드를 검증하고, 실패 이유를 포함해 한 번 재시도한 뒤 재실패 시 전용 422를 반환한다.
- `operation_for_edit_goal`로 operation 결정 규칙을 공통화하고, Markdown 생성의 최초 호출과 재시도가 같은 정규화·검증 경로를 사용하도록 정리한다.
- 연동 계약: `docs/spec/agent-markdown-contract.md`, `4.3 edit`, `4.4 generated_markdown`, `7. 오류 처리`; `docs/spec/llmpipeline-backend-output-contract.md`, `3.1 Markdown Edit`, `3.2 Markdown Create`, `3.3 Markdown 계약 오류`
- 구현 위치: `llmPipeline/app/modules/agent/infrastructure/chat_completions_turn_router.py`, `_local_guard`; `llmPipeline/app/modules/markdown_edit/infrastructure/chat_completions_markdown_editor.py`, `generate_markdown`
