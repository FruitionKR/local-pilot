# 2026-07-21 Backend 이슈 — 이메일 인증 기반 회원가입 계약 (해결)

Figma 회원가입·비밀번호 재설정 화면에 필요한 이메일 인증 API가 없던 문제. 기존 이슈는 `docs/issue/backend/2026-07-16.md`의 `3. 인증 화면 도입을 위한 API 계약 보완`에서 이관됐고, 2026-07-21 백엔드 구현으로 해소됐다.

## 조치 (구현 완료)

- 인증번호 발급 `POST /api/auth/email-verifications`(purpose=signup|password_reset), 검증 `POST /api/auth/email-verifications/{id}/confirm`, 비밀번호 재설정 `POST /api/auth/password-reset` 추가.
- `POST /api/auth/signup`에 `verification_token`을 필수로 추가 — 중복 검사 후 토큰 검증·소비.
- `email_verifications` 테이블(Flyway `V6`) 추가. 인증번호·`verification_token`은 SHA-256 해시만 저장하고, 새 코드 발급 시 같은 (email, purpose)의 미소비 코드를 폐기.
- 재요청 cooldown·일일 상한(429), 코드 만료·오입력·시도 초과, 토큰 1회성·재사용 차단 정책 적용(설정 키 `app.auth.email-verification.*`).
- 회원가입은 중복 이메일 409(존재 노출), 비밀번호 재설정은 계정 존재 여부와 무관하게 동일 응답(존재 무노출) + 성공 시 해당 사용자 refresh token 전체 폐기.

## 확정 결정

- 메일 발송: dev 로그 stub(`LoggingEmailVerificationSender`) + 로컬 `dev-fixed-code=9700`, 운영 전 SMTP 교체.
- 비밀번호 정책: 현행 8~72자 유지 + 오류 code 명확화.
- `아이디 찾기`: 현행 유지(프론트 비활성 placeholder 버튼, 백엔드 endpoint 미추가 — 로그인 아이디=이메일이고 제2 검증 채널이 없어 의미 있는 구현 불가).

## 검증

- user 패키지 테스트 54개 통과(`EmailVerificationServiceTest` 13, `AuthControllerTest` 20 포함).
- 전체 컨텍스트 로딩 테스트 통과 — Testcontainers Postgres에 `V6` 적용 + `ddl-auto=validate` 매핑 정합성 확인.

## 남은 주의사항 (백엔드 외)

- 프론트엔드: 임시 인증번호(9700)·인증 전 signup 선호출 제거 후 발급→검증→가입 재배선 → `docs/issue/frontend/2026-07-21.md`.
- 운영 전: `dev-fixed-code` 빈값 유지, 발송 sender를 실제 메일 발송 구현으로 교체.

## 확정 계약·관련 위치

- API 계약: `docs/spec/api/auth.md` — `POST /api/auth/email-verifications`, `.../confirm`, `POST /api/auth/signup`, `POST /api/auth/password-reset`, `이메일 인증 설정` 섹션.
- 구현: `backend/src/main/java/fruition/user/**`(service `EmailVerificationService`, controller `AuthController`), 마이그레이션 `backend/src/main/resources/db/migration/V6__add_email_verifications.sql`.
