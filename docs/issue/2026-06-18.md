# 2026-06-18 이슈

## 미결 이슈

### 1. MinIO 원본 문서 조회 API 추가 필요

**현황**

프론트엔드에서 원본 문서를 클릭하면 실제 raw 원본 파일이 아니라 `source:{document_id}` Wiki page를 연다.
현재 원본문서 패널은 `GET /api/wiki/pages/{wiki_page_id}`를 호출하고, 백엔드는 `wiki_pages.markdown_uri`가 가리키는 MinIO markdown을 읽어 `markdown` 필드로 반환한다.

원본 raw 파일은 업로드 시 MinIO의 `sources/documents/{document_id}/original`에 저장되고, DB `documents.source_uri`에 해당 경로가 기록된다.
하지만 이 MinIO 원본 객체를 프론트엔드가 직접 조회하거나 preview/download할 수 있는 백엔드 API는 아직 없다.

**문제**

사용자가 기대하는 "원본 문서"와 현재 화면에 표시되는 "source page"가 다르다.
PDF 또는 Markdown 원본을 그대로 확인하려면 `documents.source_uri`를 기준으로 MinIO 객체를 읽어 내려주는 백엔드 endpoint가 필요하다.

**백엔드 작업**

후보 endpoint:

```text
GET /api/documents/{document_id}/original
```

구현 방향:

- `document_id`로 `documents` row를 조회한다.
- `Document.sourceUri`의 MinIO object key를 사용해 `MinioClient.getObject()`로 원본 파일을 읽는다.
- 응답에는 `Document.mimeType` 기반 `Content-Type`을 설정한다.
- browser preview/download 정책에 맞춰 `Content-Disposition`을 정한다.
- 문서가 없으면 404를 반환한다.
- MinIO 객체가 없거나 읽기 실패 시 사용자에게 구분 가능한 오류를 반환한다.

**프론트엔드 후속 작업**

백엔드 API가 추가된 뒤 원본문서 클릭 흐름을 정리한다.

- raw 문서 클릭: `GET /api/documents/{document_id}/original` 사용
- source page 클릭: 기존 `GET /api/wiki/pages/{wiki_page_id}` 사용
- 패널 제목과 label을 raw 원본과 source page가 혼동되지 않게 분리한다.

**현재 구현 위치**

- 프론트 원본문서 패널: `frontend/app/_components/SourcePreviewPanel.tsx`
- 프론트 Wiki page 조회 API: `frontend/app/_lib/api.ts` `fetchWikiPage()`
- 프론트 raw 문서 선택 흐름: `frontend/app/_hooks/useTreeSelection.ts` `selectTreeGraphNode()`
- 백엔드 문서 조회 controller: `backend/src/main/java/fruition/document/controller/DocumentController.java`
- 백엔드 문서 service: `backend/src/main/java/fruition/document/service/DocumentService.java`
- 원본 저장 경로 생성: `backend/src/main/java/fruition/document/service/DocumentService.java` `DocumentService.upload()`
- Wiki markdown MinIO 조회 참고 구현: `backend/src/main/java/fruition/wiki/service/WikiService.java` `readMarkdown()`

**검증 기준**

- 업로드된 Markdown 원본을 `GET /api/documents/{document_id}/original`로 조회하면 원문 content가 반환된다.
- 업로드된 PDF 원본을 같은 API로 조회하면 `application/pdf`로 스트리밍된다.
- 존재하지 않는 `document_id`는 404를 반환한다.
- DB에는 있지만 MinIO 객체가 없는 문서는 일반 404와 구분 가능한 오류로 반환된다.
- 프론트에서 raw 문서와 source page preview가 서로 다른 API를 사용한다.
