# 2026-07-14

## sLLM Markdown 편집 문법 계약

### 목표

- `qwen2.5:7b`가 Markdown 문법 지시나 원문 구조를 무시한 출력을 그대로 적용하지 않게 한다.
- 단일 editor prompt를 유지하면서 보호·검증·1회 retry로 exact syntax 안정성을 높인다.
- 외부 `/agent/turn` 응답 계약과 frontend 적용 흐름은 변경하지 않는다.

### 구현 위치

- 범위와 실험 결과: `docs/spec/markdown-ai-editor-scope.md`, `11.6 문법 계약 보강`
- backend/frontend 입출력·적용 명세: `docs/spec/agent-markdown-contract.md`, `2. 요청 입력`, `4. 기존 문서 편집`, `9. Backend 연동 명세`, `10. Frontend 연동 명세`, `11. 검증 및 재현 방법`
- Markdown 보호·복원·검증: `llmPipeline/app/modules/markdown_edit/domain/markdown_output_contract.py`, `protect_markdown`, `repair_markdown_output`, `validate_markdown_output`
- editor retry와 실패 처리: `llmPipeline/app/modules/markdown_edit/infrastructure/chat_completions_markdown_editor.py`, `ChatCompletionsMarkdownEditor.generate_edit`
- editor prompt: `llmPipeline/prompts/markdown_edit.system.md`, protected token 규칙
- 평가 도구: `llmPipeline/markdown_edit_gfm_lab.py`, 17개 Markdown/GFM case

### 결과

- 구조 보호 token을 복원하고 누락·중복을 검사한다.
- 형식 계약 위반은 실패 이유를 포함해 한 번 재시도하며, 재실패 시 `MarkdownOutputContractError`를 발생시킨다.
- 보호 적용 후 첫 전체 평가는 45/51로, prompt-only 평가 33/51보다 12건 개선됐다.
- 각주, 다중 필드 frontmatter, 회의록 section, display math 집중 재평가는 12/12 통과했다.
- 최종 전체 재평가는 50/51이었고, 유일한 인라인 style 실패를 validator에 추가한 뒤 해당 case는 3/3 통과했다.

### Source-range 보존형 편집

- `cleanup`과 비구조 `style_change`는 전체 Markdown 생성 대신 원문 text range별 replacement만 sLLM에서 받는다.
- `markdown-it-py`가 CommonMark 구조를 판정하고 `markdown_source_range.py`가 token content를 원문 위치에 매핑한다.
- 원문을 재직렬화하지 않고 range만 뒤에서부터 치환하므로 잠긴 구조와 formatting은 byte 수준으로 유지된다.
- Heading, link, image, code, table, frontmatter, footnote, 영문 literal 등은 보존형 편집에서 잠근다.
- Mapping이 모호하거나 instruction이 구조 변경을 요구하면 기존 Markdown 생성·보호·검증 경로로 fallback한다.
- Source-range 전용 prompt는 867자이며 코드가 직접 선택한다. 별도 LLM routing은 추가하지 않았다.
- 최종 전체 평가는 50/51이었다. Source-range 보존형 5개 case는 모두 3/3 통과했고, 1회 실패는 `shorten`의 동의 표현에 대한 exact 문자열 평가였다.

### Pipeline 내부 편집 범위 확장

- `markdown_target_scope.py`에서 selection/current section의 실제 line fragment와 제한된 read-only 주변 문맥을 분리한다.
- `MARKDOWN_EDIT_CONTEXT_LINES` 기본값 20으로 선택 범위 앞뒤 context 크기를 제한한다.
- Source-range 지원 goal에 `translate`를 추가하고 heading, link label, table cell, footnote 본문을 visible translation segment로 처리한다.
- 목표 언어와 다른 source segment는 필수 ID로 검사하고 replacement URL 생성을 금지한다.
- `shorten`은 생성형 target fragment를 유지하되 Markdown 구조 보호, 숫자·URL·identifier anchor, 한 문장·길이·list marker validator를 적용한다.
- 두 번의 계약 실패는 `/agent/turn`에서 HTTP 422와 `markdown_output_contract_failed`로 변환하며 내부 실패 상세를 숨긴다.
- 성공 응답 계약은 유지했고 `backend`와 `frontend`는 변경하지 않았다.
- 평가 범위는 19개 case로 확장했고 최초 3회 반복 결과는 56/57이었다. 유일한 실패는 축약 동의 표현에 대한 exact 문자열 평가였다.

### 선택 경계와 장문 context 검증

- `markdown_source_range.py`의 `validate_markdown_target_boundary`가 fenced/indented code, HTML block, GFM table, frontmatter, 여러 줄 footnote definition과 display math를 부분 선택하지 못하게 한다.
- `/agent/turn`은 부분 구조 선택을 HTTP 422와 `markdown_target_crosses_structure`로 반환한다.
- 한국어 보존형 편집 결과에 원문에 없던 한자가 생기면 계약 실패로 판정하고 한 번 재시도한다.
- `markdown_agent_http_lab.py`로 실제 FastAPI `/agent/turn`과 로컬 `qwen2.5:7b` router/editor를 연결해 cleanup, structured translation, 부분 fence 차단 3/3을 확인했다.
- `markdown_context_benchmark.py`에서 1천 줄과 5천 줄 문서 모두 target 앞뒤 각 20줄만 전달했다. 실제 editor JSON 구조 기준 request payload는 각각 1,786자와 1,788자로 문서 길이와 무관하게 유지됐다.
- 전체 문서 경계 분석을 포함한 평균 전처리 시간은 1천 줄 6.828ms, 5천 줄 33.539ms였다.
- 세부 설계와 수치는 `docs/spec/markdown-ai-editor-scope.md`, `11.9 선택 경계, 실제 HTTP E2E와 장문 context 검증`에 기록했다.
