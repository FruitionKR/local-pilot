# 2026-07-14

## Wiki generation orchestration 리팩터링

### 목표

- `run_lab.py`에 섞인 의미 추출 평가·보정·재시도 정책을 `wiki_generation` application layer로 이동한다.
- LLM, debug artifact, callback/file log I/O는 application port 뒤의 infrastructure adapter로 분리한다.
- CLI/API 입력과 pipeline manifest 결과 계약은 변경하지 않는다.

### 구현 위치

- generation application use case: `llmPipeline/app/modules/wiki_generation/application/run_generation_loop.py`, `RunGenerationLoopUseCase`
- evaluator payload와 guard: `llmPipeline/app/modules/wiki_generation/application/evaluate_generation.py`, `evaluate_generation`
- concept/cluster candidate 판단: `llmPipeline/app/modules/wiki_generation/application/judge_candidates.py`, `judge_concept_update_candidates`, `judge_meaning_cluster_candidates`
- application port: `llmPipeline/app/modules/wiki_generation/application/ports.py`, `JsonCompletionPort`, generation loop port들
- LLM·debug artifact adapter: `llmPipeline/app/modules/wiki_generation/infrastructure/generation_loop_adapters.py`
- file/callback log adapter: `llmPipeline/app/modules/wiki_generation/infrastructure/pipeline_log.py`, `PipelineLog`
- compatibility entrypoint와 wiring: `llmPipeline/run_lab.py`, `_run_wiki_generation_loop`, `run_pipeline`

### 결과

- `run_lab.py`를 1,364줄에서 912줄로 줄였다.
- generation 평가 흐름은 FastAPI, Pydantic, LangGraph, 환경변수, 파일 경로를 import하지 않는 application use case가 담당한다.
- semantic extraction, evaluator completion, debug JSON, callback log는 infrastructure에 남겼다.
- candidate 판단은 `JsonCompletionPort`만 사용하며 LLM 결과의 허용 decision/relation과 대상 식별자를 검증한다.
- 기존 CLI/API 입력, evaluator retry feedback, debug artifact 파일명과 manifest 계약은 유지한다.
