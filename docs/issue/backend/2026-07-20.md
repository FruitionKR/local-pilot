# 2026-07-20 Backend 이슈

## 1. [팀원 조치 필요] 빈 문서 생성 API 부재

사이드바 컨텍스트 메뉴에서 "빈 문서 생성"(내용 없는 새 문서를 만들고 이후 편집) 기능을 붙이려 했으나, 대응하는 백엔드 endpoint가 없어 프론트 단독 구현이 불가능하다.

### 현황

- 현재 문서 생성 경로는 multipart 파일 **업로드** 하나뿐이다: `POST /api/workspaces/{workspace_id}/documents` (`fruition/document/controller/DocumentController.java:62-85`). 파일 바이트가 필수라 빈 문서를 만들 수 없다.
- `documents` 테이블은 `content_hash` NOT NULL 등 실제 콘텐츠 기반 제약이 있어(파이프라인 로그에서 `null value in column "content_hash"` 위반 확인됨), 빈 row를 단순 삽입할 수 없다.
- 삭제(`DELETE /api/workspaces/{workspace_id}/documents/{document_id}`)와 이름 변경(`PATCH .../documents/{document_id}/rename`)은 이미 존재해 프론트 배선을 완료했다. 변경 기록: `docs/changelog/frontend.md` 2026-07-20 항목.

### 필요한 계약(협의 대상)

- 빈 문서 생성 endpoint (예: `POST /api/workspaces/{workspace_id}/documents/blank`)
  - 입력: 초기 표시명(`filename`) 정도. 파일 바이트 없음.
  - 응답: 생성된 문서의 `id`, `filename`, `status`, `uploaded_at` 등 기존 `DocumentListResponse.DocumentItem`과 호환되는 형태.
- 빈 문서의 `status`·`content_hash`·`source_uri` 처리 정책 결정 필요:
  - 빈 문서는 파이프라인 처리 대상인가(위키 생성 등), 아니면 순수 편집용 placeholder인가.
  - `content_hash` NOT NULL 제약을 빈 문서에 어떻게 만족시킬지(빈 콘텐츠 해시 허용 vs. nullable 완화).
- 편집 후 내용 저장 endpoint 필요 여부(빈 문서를 만든 뒤 본문을 채우는 흐름이면 문서 본문 update API도 함께 설계).

### 프론트 상태

- 빈 문서 생성은 백엔드 계약 확정 전까지 미구현으로 둔다.
- 관련 프론트 위치: 컨텍스트 메뉴 `frontend/app/_components/document-sidebar/ContextMenu.tsx`, 트리 핸들러 `frontend/app/_hooks/useProjectTree.ts`, API 클라이언트 `frontend/app/_lib/api.ts`.
