# 2026-07-24 Backend 이슈

## Markdown 외 문서 형식 확장

### 현재 범위

- 현재 업로드 API는 PDF와 Markdown 원본 자료를 허용한다.
- Markdown은 편집 상태를 생성하고 기존 Wiki pipeline을 실행한다.
- 비-Markdown은 `uploaded` 상태의 읽기 전용 원본으로 저장하고 변환 pipeline을 실행하지 않는다.
- Markdown을 포함한 내보내기 기능은 후속 작업으로 진행한다.
- task 구현 중 `frontend/` 또는 `llmPipeline/` 변경이 필요하면 해당 영역을 직접 수정하지 않고 이 문서에서 관리한다.

### 후속 작업

- PDF, DOCX 등 원본 자료의 지원 형식과 MIME 정책을 정의한다.
- 기존 `llmPipeline`의 PDF 문서 복원 CLI를 worker 또는 API로 연결하고 저장 경로를 정의한다.
- 변환 작업의 run ID를 Wiki 생성 pipeline run ID와 분리한다.
- 변환 결과 callback의 인증, 멱등성, checksum 및 크기 제한 계약을 정의한다.
- 변환 완료 후 Wiki pipeline을 시작하는 순서를 정의한다.
- Markdown 원문 다운로드 API를 구현한다.
- PDF 등 Markdown 외 내보내기 형식과 이미지·첨부 자원의 포함 정책을 정의한다.
- PDF를 `.md` 복제본으로 만드는 기능은 변환 편집본 등록이 완료된 뒤 `POST /duplicate`와 연결한다.

### 기존 코드와의 충돌

현재 backend는 Markdown 업로드 후 `DocumentService.requestProcessingAfterCommit`에서 처리 큐를 등록한다. `llmPipeline`의 `POST /pipeline/runs`는 PDF 변환 API가 아니며, `extracted_text_uri`가 없는 비-Markdown 문서를 처리하지 못한다. Markdown 외 업로드는 원본만 저장하고, 향후 지원할 때 변환 worker 시작과 Wiki pipeline 시작을 분리해야 한다.
