# Backend 이슈 — 2026-08-05

## 직접 생성·복제 Markdown 재ingest 실패

`POST /api/workspaces/{workspace_id}/documents/markdown`으로 직접 생성하거나 기존 Markdown을 복제한 문서는 `documents.source_uri`가 `null`입니다. 이후 `POST /api/workspaces/{workspace_id}/documents/{document_id}/ingest`를 호출하면 `DocumentService.ingest()`가 이 값을 MinIO object key로 그대로 넘겨 `500 INTERNAL_SERVER_ERROR`가 발생합니다.

재현 결과:

- 직접 생성 Markdown 응답: `status=completed`, `source_uri=null`
- 해당 문서 재ingest: `500 INTERNAL_SERVER_ERROR`
- 파일 업로드로 생성해 `source_uri=sources/documents/{document_id}/original`이 있는 Markdown은 재ingest `202` 성공

관련 위치:

- 직접 생성: `backend/src/main/java/fruition/document/service/DocumentService.java` — `createMarkdownDocument()`
- 복제 생성: `backend/src/main/java/fruition/document/service/DocumentService.java` — `duplicate()`
- 재ingest: `backend/src/main/java/fruition/document/service/DocumentService.java` — `ingest()`
- API: `backend/src/main/java/fruition/document/controller/DocumentController.java` — `POST /documents/markdown`, `POST /documents/{document_id}/ingest`

완료 조건:

- [ ] 직접 생성 Markdown의 재ingest가 `202`를 반환함
- [ ] 복제 Markdown의 재ingest가 `202`를 반환함
- [ ] 재ingest 전에 편집본이 표준 MinIO 경로에 저장되고 `documents.source_uri`가 그 경로를 가리킴
- [ ] 기존 업로드 Markdown 재ingest 동작이 유지됨

## `INTERNAL_CALLBACK_TOKEN` 양방향 내부 통신 인증

llmPipeline은 Backend 요청에 `X-Internal-Token` 검증을 적용했습니다. 현재 Backend→llmPipeline 요청에는 같은 헤더를 보내지 않아 Query·Ingest·Restore·Schema·Lint·Agent 호출이 `401`로 거절됩니다. 진행 로그·Query event callback은 llmPipeline이 헤더를 보내지만 Backend에서 아직 검증하지 않습니다.

Backend 작업 범위:

- 다음 requester의 모든 요청에 `X-Internal-Token: ${app.internal.callback-token}` 추가
  - `DocumentProcessingRequester`
  - `PipelineQueryRequester`
  - `PipelineWikiSchemaRequester`
  - `PipelineWikiMaintenanceRequester`
  - `PipelineRestoreRequester`
  - `PipelineWikiPageRequester`
  - `PipelineAgentRequester`
- `DocumentPipelineController`의 `POST /api/documents/{document_id}/pipeline-events`에서 같은 토큰 검증
- `QueryRunController`의 `POST /api/query/runs/{requestId}/events/callback`에서 같은 토큰 검증
- 기존 `OperationCallbackController`의 상수 시간 비교 규칙을 공통 검증기로 재사용

완료 조건:

- [ ] Backend→llmPipeline 요청이 모두 같은 `X-Internal-Token`을 전송함
- [ ] 결과·진행 로그·Query event callback이 토큰 누락·불일치 시 `401`을 반환함
- [ ] 토큰 일치 시 기존 ingest·query·schema·lint·restore·agent 흐름이 유지됨
- [ ] 현재 llmPipeline 수신 검증과 연결해 `401` 장애를 해소함
