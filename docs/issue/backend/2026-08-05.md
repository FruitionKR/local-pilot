### 변경 이유와 영향

- 이미지 bytes를 문서 저장과 연결하기 전에 DB 무결성 경계를 먼저 고정하기 위한 기반 작업이다.
- migration은 최신 `dev`의 `V16__add_wiki_page_versions.sql`,
  `V17__add_wiki_page_deleted_status.sql`과 충돌하지 않도록 asset은 `V18`, orphan은 `V19`를 사용한다.
- 기존 document API와 제품 동작은 아직 변경하지 않는다.

- 참조가 남은 asset의 직접 삭제가 FK로 거절됨을 확인
- multipart parser가 이미지 없는 metadata 저장을 허용하고 placeholder와 file part의 정확한 대응을
  검증함을 확인했다. 실제 Controller 연결은 MinIO 저장·보상 경계와 함께 구현한다.
- PNG·JPEG·GIF는 실제 decoder로, WebP는 RIFF와 VP8/VP8L/VP8X 구조로 형식과 dimension을 검증한다.
  요청 MIME과 파일명은 형식 판정에 사용하지 않으며 bytes와 검증된 MIME을 그대로 다음 저장 단계에
  전달한다.
- asset 전용 storage adapter는 bucket·storage key를 API 응답에 노출하지 않고, coordinator가 여러
  object 중 일부 저장 실패 또는 후속 DB 실패 시 호출할 수 있는 보상 삭제 경계를 제공한다.
- 보상 삭제에 실패한 object는 원래 transaction과 분리된 `REQUIRES_NEW` transaction으로
  `document_asset_orphans`에 기록한다. 같은 storage key의 반복 실패는 retry count와 마지막 오류를
  갱신한다.
- CommonMark parser로 실제 이미지 destination의 관리 asset만 추출하고, 다른 workspace·존재하지
  않는 asset을 거절한다. 문서 저장 시 reference diff와 `unreferenced_since`를 동기화하며 문서
  복제는 asset row나 object를 복사하지 않고 reference만 복사한다.
- `PUT /documents/{document_id}/content`는 기존 이미지 없는 개별 part와 새 `metadata` JSON 방식을
  함께 수용한다. 새 방식은 권한·version 사전 검사, 이미지 검증, MinIO 선저장 후 DB transaction에서
  version을 다시 검사하고 본문·asset·reference를 원자 반영한다. 성공 응답은 치환된 최종 Markdown,
  새 version과 attachment–asset 매핑을 반환하며 DB 실패·충돌에는 신규 object를 보상 삭제한다.
- `GET /api/workspaces/{workspace_id}/assets/{asset_id}/content`는 workspace 멤버에게만 MinIO stream을
  반환하며 다른 workspace asset과 비멤버는 같은 `404`로 숨긴다. 검증 MIME·길이·private 1시간 cache,
  SHA-256 ETag와 `X-Content-Type-Options: nosniff`를 반환하고 조건부 요청은 `304`로 처리한다.
