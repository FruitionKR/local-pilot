## 1. wiki_pages 잔재 unique constraint `uq_wiki_pages_type_slug` 제거

- 현재 DB `wiki_pages`에 unique constraint 2개 공존:
  - `uq_wiki_pages_workspace_type_slug (user_id, workspace_id, page_type, slug)` — 현행. `fruition/wiki/domain/WikiPage.java:9`에 정의됨.
  - `uq_wiki_pages_type_slug (page_type, slug)` — 과거 entity 정의의 잔재. 현재 코드 어디에도 정의 없음. JPA `ddl-auto=update`는 기존 constraint를 삭제하지 않아 DB에만 남아 있음.
- 영향: llmPipeline이 wiki page를 workspace 단위 constraint 대상으로 upsert(`ON CONFLICT (user_id, workspace_id, page_type, slug)`)하는데, 잔재 constraint가 전역 `(page_type, slug)` 중복을 먼저 막아 문서 재실행 run이 `duplicate key value violates unique constraint "uq_wiki_pages_type_slug"`로 실패. 상세 재현: `docs/issue/ai/2026-07-16.md` 이슈 2.
- 조치: dev DB에서 `ALTER TABLE wiki_pages DROP CONSTRAINT uq_wiki_pages_type_slug;` 실행 및 팀원 로컬 DB 반영 방법 공지 (초기화 또는 동일 DDL 실행). 마이그레이션 도구 도입 전까지는 수동 DDL로 처리.
