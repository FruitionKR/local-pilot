## 2. [팀원 조치 필요] Flyway + FK CASCADE 도입에 따른 로컬 DB 최초 1회 리셋

**대상**: 이 브랜치를 pull하는 모든 백엔드 개발자. **최초 1회만** 필요.

### 배경

- 스키마 관리가 `ddl-auto=update` → **Flyway + `ddl-auto=validate`**로 바뀌었고, FK CASCADE(`V3`)까지 도입됐다.
- 기존 `update`로 쌓인 로컬 DB는 `flyway_schema_history`가 없어 `baseline-on-migrate`로 v1 마킹만 된 뒤 V2·V3가 기존(잔재/고아 포함) 스키마 위에 실행된다.
- 특히 과거 workspace 삭제 버그로 남은 **고아 wiki_pages/링크**가 있으면 `V3`의 FK 추가가 위반으로 실패해 **앱 기동이 막힌다.**

### 조치 (최초 1회)

```bash
# infra/ 에서 — 로컬 DB 볼륨 삭제(로컬 데이터는 소모성이라 무방)
docker compose -f docker-compose.dev.yml down -v && docker compose -f docker-compose.dev.yml up -d
# backend/ 에서 — 빈 DB에 Flyway가 V1~V3를 깨끗이 적용
./gradlew bootRun
```

이후부터는 `git pull && ./gradlew bootRun`만 하면 새 마이그레이션이 자동 적용된다.
