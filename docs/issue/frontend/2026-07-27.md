# Frontend 이슈 — 2026-07-27

## AI 편집 저장 시 `source=agent` 전송 (버전 롤백 연동)

백엔드에 문서 콘텐츠 **버전 이력·롤백**이 추가됐습니다. 버전 스냅샷은 **AI 편집을 사용자가 승인·저장하는 시점(`source=agent`)에만** 기록됩니다. 프론트가 저장 요청에 `source`를 실어줘야 롤백 목록에 해당 시점이 남습니다. (백엔드 코드는 준비 완료, 프론트 연동만 남음.)

### 계약: `PUT /api/workspaces/{workspace_id}/documents/{document_id}/content`

`multipart/form-data`, 파트 구성:

| 파트 | 필수 | 설명 |
|------|------|------|
| `markdown` | 필수 | 저장할 전체 Markdown 본문 |
| `base_version` | 필수 | 클라이언트가 조회한 현재 문서 version(정수) |
| `source` | 선택 | `"agent"`이면 버전 스냅샷을 남김(= AI 편집 승인 저장). 생략/그 외 값이면 수동 저장으로 스냅샷 없음 |

- **AI 편집 결과를 사용자가 "적용/승인"해서 저장**할 때: `source=agent` 를 함께 보낸다.
- **일반 수동 저장(Ctrl+S 등)**: `source` 를 보내지 않는다(스냅샷 미기록).
- 응답/충돌 규칙은 기존과 동일: 내용이 같으면 no-op, `base_version` 불일치면 409(`DOCUMENT_VERSION_CONFLICT`).

### 롤백 UI용 조회/복원 API (신규)

- `GET  /documents/{document_id}/versions` — 버전 이력 목록(최신순, 본문 제외 메타데이터: `version`, `content_hash`, `created_by`, `created_at`)
- `GET  /documents/{document_id}/versions/{version}` — 특정 버전 전체 Markdown 본문(미리보기용)
- `POST /documents/{document_id}/versions/{version}/restore` — 해당 버전으로 복원. body: `{ "base_version": <현재 version> }`. 비파괴적(이력 유지), version 충돌 시 409.

### 참고(백엔드 위치)

- 저장/버전 서비스: `backend/src/main/java/fruition/document/service/DocumentService.java` (`saveContent`의 `source` 파라미터, `listContentVersions`/`getContentVersion`/`restoreContentVersion`)
- 컨트롤러: `backend/src/main/java/fruition/document/controller/DocumentController.java` (`PUT /content`의 `source` 파트, `/versions*` 엔드포인트)
- 마이그레이션: `backend/src/main/resources/db/migration/V12__add_document_content_versions.sql`

## 문서 편집 잠금(활성 편집 추적) 연동

한 문서를 동시에 두 사람이 편집하지 못하게 **편집 잠금(lease)** 이 추가됐다. **A가 편집 중이면 B는 읽기 전용**으로 열람만 가능하고 편집 진입·저장이 막힌다(423). 프론트가 에디터 생명주기에 맞춰 잠금 API를 호출해야 한다. (백엔드 준비 완료, 프론트 연동만 남음.)

### 에디터 생명주기

기준 경로: `/api/workspaces/{workspace_id}/documents/{document_id}/edit-lock`

| 시점 | 호출 | 처리 |
|------|------|------|
| 에디터 **진입** | `POST /edit-lock` | `200` → 편집 가능. **`423`** → 다른 사용자 편집 중, 응답 본문 `{holder_user_id, holder_display_name, expires_at}`로 "○○님 편집 중" 표시 + **읽기 전용** |
| 편집 **중(주기적)** | `POST /edit-lock/heartbeat` | 약 **15초**마다. `200`이면 연장. **`409 EDIT_LOCK_LOST`** 오면 잠금 상실 → 편집 중단·읽기 전용 전환 후 재획득 유도 |
| 에디터 **종료** | `DELETE /edit-lock` | 멱등. 탭 닫기(`beforeunload`)에서도 시도 |

- 잠금 TTL은 백엔드 기본 **45초**(`app.document.edit-lock.ttl-seconds`). heartbeat를 놓쳐 만료되면 다음 사람이 획득 가능.

### 쓰기 요청의 423 처리

`PUT /content`·`POST /agent/turn`·`POST /versions/{v}/restore`·`POST /documents/{id}/ingest`는 **다른 사용자가 잠금 보유 중이면 `423 DOCUMENT_EDIT_LOCKED`** 로 거절된다. 이 응답을 받으면 "다른 사용자가 편집 중"으로 안내하고 저장을 막는다. (잠금 보유는 강제가 아니므로, 아무도 편집 안 하면 기존처럼 저장된다.)

### 편집 중 여부 표시

`GET /documents/{id}` 응답에 **`edit_lock` 필드**가 추가됐다. `null`이면 아무도 편집 안 함, 값이 있으면 `{holder_user_id, holder_display_name, expires_at}` — 문서 목록/상세에서 "편집 중" 배지 표시에 사용.

### 참고(백엔드 위치)

- 서비스/컨트롤러: `DocumentEditLockService`, `DocumentEditLockController`
- enforcement: `DocumentService.saveContent/ingest`, `AgentTurnService.turn`의 `requireWritable`
- 마이그레이션: `V13__add_document_edit_locks.sql`
- 설계: `docs/design/document-edit-lock.md`
