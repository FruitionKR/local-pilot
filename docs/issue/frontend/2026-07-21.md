# 2026-07-21 Frontend 이슈

## 1. 이메일 인증 화면 실제 API 재배선

백엔드 이메일 인증 API가 구현 완료됐다(해결 기록 `docs/backlog/issue-2026-07-21.md`, 계약 `docs/spec/api/auth.md`). 프론트의 임시 우회를 실제 API 흐름으로 교체해야 한다.

### 현재 임시 우회 (제거 대상)

- 개발용 임시 인증번호 `9700`(`isTemporaryCode`)으로 인증 완료를 흉내낸다.
- `인증 요청` 단계에서 `signupWithEmail(email, password)`를 선호출한다 — 사용자가 인증을 중단해도 계정이 생성되는 임시 처리.
- 관련 위치: `frontend/app/login/page.tsx`의 `handleSignupRequest`·회원가입 인증 완료 effect, API 클라이언트 `frontend/app/_lib/api.ts`.

### 필요한 재배선 (계약: `docs/spec/api/auth.md`)

- 회원가입: `POST /api/auth/email-verifications`(purpose=signup) → `POST /api/auth/email-verifications/{verification_id}/confirm`(code) → `POST /api/auth/signup`(발급받은 `verification_token` 포함) 순서로 호출.
- 비밀번호 재설정: 동일하게 발급·검증(purpose=password_reset) 후 `POST /api/auth/password-reset`(email, new_password, verification_token).
- 오류 code 처리: `DUPLICATE_EMAIL`(409), `INVALID_VERIFICATION_CODE`·`VERIFICATION_CODE_EXPIRED`·`VERIFICATION_CODE_ATTEMPTS_EXCEEDED`(400), `VERIFICATION_RATE_LIMITED`(429, `Retry-After` 헤더), `INVALID_VERIFICATION_TOKEN`(400).
- 로컬 개발 편의는 백엔드 `app.auth.email-verification.dev-fixed-code`(예: 9700) 설정으로 대체 — 프론트에 고정 코드를 두지 않는다.

### 완료 조건

- 인증 요청 단계에서 계정이 생성되지 않는다(선 signup 호출 제거).
- 유효한 `verification_token` 없이는 회원가입·비밀번호 재설정이 완료되지 않는다.
- 임시 인증번호(9700) 클라이언트 분기가 제거된다.
