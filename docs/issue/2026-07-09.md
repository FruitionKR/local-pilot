# 2026-07-09 이슈 및 의사록

## Chat Wiki 누적 플로우 정리

### 배경

- chat source page 누적 대상은 `document_id`로 특정한다.
- 기존 source page가 있는 `full` 누적에서 백엔드가 이미 저장된 chat Q&A를 제외하고 새로 누적할 대상만 Markdown으로 직렬화하면, llmPipeline에는 `document_id`와 선택적 `input_markdown`이 전달된다.
- 백엔드는 이미 저장된 chat Q&A를 제외하고 새로 누적할 대상만 llmPipeline에 전달하는 방향으로 본다.
- `document_id`는 source page 선택 key이고, `input_markdown`은 기존 source page가 있는 `full` 누적에서 신규 pair를 직접 넘길 때 쓰는 선택 입력이다.

### 결정

- 일반 문서 ingest와 채팅 Wiki page화 API를 분리한다.
  - 일반 문서: `POST /pipeline/runs`
  - 채팅 Wiki page화: `POST /chat-wiki/runs`
  - 채팅 API에서는 `selection_mode`가 필수이며, `full` 또는 `partial`만 허용한다.
- `partial` 선택은 채팅 전용 prompt로 처리한다.
  - 기존 source page 누적 맥락을 별도로 붙이지 않는다.
  - 선택된 일부 문답은 독립 입력처럼 semantic extraction을 수행한다.
- `full` 선택은 기존 source page가 있으면 누적 플로우를 사용한다.
  - LLM prompt에는 기존 source page markdown 본문을 넣는다.
  - 기존 `core_concepts`, `section_candidates`, `mentions`는 prompt 판단용이 아니라 코드 비교용 metadata로 유지한다.
  - `summary`는 기존 요약 뒤에 새 요약을 붙이는 append가 아니라, 기존 source page 문맥과 새 대화 내용을 함께 본 전체 source page 요약으로 다시 작성한다.
- `full` 선택이지만 기존 source page가 없으면 최초 생성 플로우로 처리한다.
  - prompt는 `partial`과 같은 chat prompt를 사용한다.
  - 생성된 source page는 같은 `document_id`로 저장되어 이후 `full` 누적 대상이 된다.
- LLM은 승격 여부를 판단하지 않는다.
  - LLM은 기존 source page 본문을 읽고 새 chat Q&A에서 평소처럼 `core_concepts`, `section_candidates`, `mentions`를 다시 추출한다.
- ingest는 cross-source 승격 판단이나 cluster evidence 병합을 수행하지 않는다.
  - 새 결과의 `concept_ledger`에 core가 나오면 현재 입력 근거와 같은 source page 안에 이미 축적된 section/mention 근거로 concept page를 생성한다.
  - 기존 source artifact에 없던 slug가 새 결과의 core concept으로 나오면 신규 core concept으로 추가한다.
  - 기존 source page의 `core_concepts`, `section_candidates`, `mentions`는 같은 source page 문맥 보존과 누적 조립용으로 병합한다.
  - 기존 section/mention이 새 core와 의미상 겹치면 같은 source page 내부 누적으로 보고 해당 근거를 새 core에 붙인다.
  - 다른 source page나 active cluster에 모인 외부 evidence는 ingest 단계에서 끌어오지 않는다.
  - lint용 승격 status/hint는 필요하지만, 이번 코드 수정 범위에서는 제외한다.
- 기존 source artifact의 `evidence_claims`는 prompt context나 concept page evidence 병합 입력으로 사용하지 않는다.
- semantic extraction prompt는 세 가지로 분리한다.
  - 일반 문서 prompt: 기존 문서 ingest용
  - chat prompt: `partial` 또는 기존 source page가 없는 최초 `full`용
  - chat append prompt: 기존 source page가 있는 `full` 누적용

### 필요한 llmPipeline 반영

- `/pipeline/runs`에서는 `selection_mode` 입력을 거부한다.
- `/chat-wiki/runs`를 추가하고 `document_id`, `selection_mode`를 필수로 검증한다.
- `/chat-wiki/runs`의 `input_markdown`은 선택 필드다.
  - 기존 source page가 있는 `full` 누적에서 값이 있으면 신규 pair 입력으로 우선 사용한다.
  - 값이 없으면 기존처럼 `document_id`로 저장된 Markdown을 로드한다.
  - 어느 경우든 source page 누적 key는 `document_id`로 유지한다.
- chat full 누적의 전체 흐름은 다음과 같다.
  1. backend가 `document_id`로 누적 대상 source page를 결정한다.
  2. backend가 이미 처리된 pair를 제외하고 신규 pair만 `input_markdown`으로 직렬화한다.
  3. llmPipeline이 `document_id`로 기존 source page markdown과 `source_extraction_artifact`를 조회한다.
  4. llmPipeline이 `input_markdown`을 이번 실행 입력으로 읽는다.
  5. 기존 source page가 있으면 chat append prompt로 새 Q&A만 추출한다.
  6. 기존 source metadata와 새 extraction 결과를 append draft로 조립한다.
  7. source accumulation evaluator가 summary/key points/observations/categories를 평가해 병합 결과를 반환한다.
  8. 코드가 evaluator 결과와 core/section/mention 병합 규칙을 적용해 source page와 concept page를 생성한다.
- chat 최초 full의 흐름은 다음과 같다.
  1. backend가 앞으로 누적할 `document_id`를 정한다.
  2. backend가 처리 대상 pair를 저장된 Markdown 문서로 준비한다.
  3. llmPipeline이 `document_id`로 기존 source page를 조회한다.
  4. 기존 source page가 없으면 chat prompt로 최초 source page를 생성한다.
  5. 생성된 source page는 `document_id`로 저장되어 다음 full 요청의 누적 대상이 된다.
- chat partial의 흐름은 다음과 같다.
  1. backend가 선택된 pair를 저장된 Markdown 문서로 준비한다.
  2. llmPipeline이 `document_id`로 저장된 Markdown을 읽는다.
  3. llmPipeline은 기존 source page context를 붙이지 않는다.
  4. chat prompt로 선택 pair 묶음을 독립 source page로 생성한다.
- 기존 source context 조회는 `source_extraction_artifact`만이 아니라 기존 source page markdown도 함께 가져와야 한다.
- semantic extraction prompt에는 기존 `core/section/mention` 요약 metadata가 아니라 기존 source page markdown 본문을 넣어야 한다.
- 기존 `core_concepts`, `section_candidates`, `mentions`는 pipeline 내부에서 source page 조립용 metadata로만 보관한다.
- source page 조립 시에는 기존 metadata와 새 extraction 결과를 코드에서 병합해 누적 source page를 만든다.
- source page의 key points, observations, categories, core/section/mention은 기존 항목을 선행시키고 새 항목을 뒤에 누적한다.
- source page 누적은 먼저 append draft를 만든 뒤 source accumulation evaluator가 평가하고 수정한 구조화 결과를 적용한다.
  - evaluator는 의미적으로 같은 key point, observation, category를 하나로 합치고 source refs를 병합한다.
  - source page의 summary는 evaluator가 기존 source page markdown과 새 source blocks를 함께 보고 전체 요약으로 재작성한다.
  - LLM은 Markdown 전체를 직접 만들지 않고 `summary`, `key_points`, `observations`, `categories`의 구조화된 수정 결과만 반환한다.
- concept page 생성 시에는 같은 source page의 기존 section/mention evidence를 새 core evidence로 병합한다.
- concept page 생성 시에도 다른 source page나 active cluster의 evidence는 병합하지 않는다.
