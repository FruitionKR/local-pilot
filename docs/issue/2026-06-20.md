# 2026-06-20 이슈

## 완료된 수정

### 1. 채팅 "찾은 자료" 카드 중복 표시 — 프론트엔드 임시 dedup 처리

**현황**

에이전트 패널의 "찾은 자료 N건" 카드 목록에 동일한 문서가 여러 번 표시되는 현상이 확인됐다.

**원인 분석**

- llmPipeline `/query` 응답은 `related_pages`(페이지 단위)와 `evidence_snippets`(문장 단위)를 모두 반환한다.
- 백엔드 `QueryService`는 `evidence_snippets`만 `chat_message_references` 테이블에 저장한다. `related_pages`는 저장하지 않는다.
- `GET /api/chat/messages` 응답의 `references` 필드는 `evidence_snippets` 기반이다.
- 하나의 페이지에서 여러 문장이 근거로 사용되면 동일한 `wiki_page_id`를 가진 `reference` 행이 여러 개 생성된다.
- 프론트엔드 `AgentBody.tsx`가 `message.references`를 그대로 순회하며 카드를 렌더링하므로 같은 페이지 카드가 중복된다.

**적용된 수정 (임시)**

`frontend/app/_components/agent-panel/AgentBody.tsx`의 `renderAssistantThread` 함수에서 references를 렌더링하기 전에 `pageId` 기준으로 중복을 필터링하도록 수정했다.

```tsx
// pageId Set으로 중복 제거 후 슬라이스
const seenPageIds = new Set<string>();
message.references
  .filter((reference) => {
    const pageId = reference.wiki_page_id
      || (reference.document_id ? makeSourceId(reference.document_id) : null);
    if (!pageId || seenPageIds.has(pageId)) return false;
    seenPageIds.add(pageId);
    return true;
  })
  .slice(0, MAX_RESULT_CARDS)
  .map(...)
```

**근본 해결 필요 (백엔드)**

이 수정은 증상 완화다. 근본 원인은 백엔드 저장 구조에 있다.
2026-06-18 이슈 문서의 "이슈 2 — 채팅 찾은 자료를 `related_pages` 기준으로 복원하도록 저장 구조 정리 필요"를 참고한다. ([docs/issue/2026-06-18.md](./2026-06-18.md))

핵심 작업:
- `chat_message_related_pages` 테이블 추가
- `QueryService.query()`에서 `related_pages`도 저장
- `GET /api/chat/messages` 응답에 `related_pages` 필드 추가
- 프론트엔드 "찾은 자료" 렌더링 기준을 `message.references` → `message.related_pages`로 교체 후 현재 임시 dedup 코드 제거

**현재 구현 위치**

- 임시 수정: `frontend/app/_components/agent-panel/AgentBody.tsx` `renderAssistantThread()` 내 references 렌더링 블록

### 2. 그래프 노드 선택 이펙트가 폴링 후 사라지는 문제 수정

**현황**

트리 또는 채팅에서 노드를 선택하면 그래프 캔버스에 포커스 하이라이트 이펙트가 표시된다. 그런데 문서 처리 중(`status: processing`) 백엔드 폴링이 실행된 뒤 이펙트가 사라지는 현상이 있었다.

**원인 분석**

`useBackendData.ts`에서 처리 중인 문서가 있을 때 3초마다 `refreshBackendData()`를 호출한다.

```ts
const PROCESSING_POLL_INTERVAL_MS = 3000;

useEffect(() => {
  if (!hasProcessingDocuments) return;
  const intervalId = window.setInterval(() => void refreshBackendData(), PROCESSING_POLL_INTERVAL_MS);
  return () => window.clearInterval(intervalId);
}, [hasProcessingDocuments, refreshBackendData]);
```

폴링으로 새 `wikiGraph`가 업데이트되면 `buildGraphFromBackend()`가 새 nodes/links 배열을 생성하고, `useGraphCanvas`에서 `graphSignature`(노드·링크 ID 조합)가 변경된다.

`graphSignature`가 바뀌면 그래프 재초기화 effect가 실행된다:

```ts
useEffect(() => {
  // ...
  selectedNodeIdRef.current = null;      // ← 포커스 무조건 초기화
  hoveredNodeIdRef.current = null;
  nodeHoverAmountsRef.current = {};      // ← 애니메이션 상태 초기화
  drawGraphRef.current();
}, [graphSignature, initialNodePositions]);
```

이로 인해 외부에서 선택한 노드(`externalFocusedNodeIdRef`)가 있어도 포커스 상태가 지워졌다.
이후 re-apply effect(`[focusedNodeId, nodeById]` deps)가 포커스를 복구하지만, `nodeHoverAmountsRef`는 이미 비워져 하이라이트 애니메이션이 0에서 다시 시작된다. 결과적으로 이펙트가 순간 사라졌다가 ~320ms 후 페이드인되는 현상이 발생했다.

**적용된 수정**

`frontend/app/_components/graph/useGraphCanvas.ts`의 재초기화 effect에서, 그래프가 바뀔 때 `externalFocusedNodeIdRef.current`를 확인해 외부 포커스가 있으면 그 상태를 보존하도록 수정했다.

```ts
// 수정 전
selectedNodeIdRef.current = null;
hoveredNodeIdRef.current = null;
nodeHoverAmountsRef.current = {};

// 수정 후
const externalId = externalFocusedNodeIdRef.current;
selectedNodeIdRef.current = externalId;
hoveredNodeIdRef.current = externalId;
nodeHoverAmountsRef.current = externalId
  ? { [externalId]: nodeHoverAmountsRef.current[externalId] ?? 1 }
  : {};
```

외부 포커스가 없으면 기존처럼 초기화하고, 있으면 해당 노드의 기존 hover 애니메이션 값(없으면 1)을 유지한다. 이로써 폴링 후에도 하이라이트 이펙트가 끊기지 않는다.

**현재 구현 위치**

- 수정 위치: `frontend/app/_components/graph/useGraphCanvas.ts` — `[graphSignature, initialNodePositions]` deps effect 내 refs 초기화 블록
- 관련 폴링 로직: `frontend/app/_hooks/useBackendData.ts` `PROCESSING_POLL_INTERVAL_MS`
- 그래프 포인터 외부 포커스 가드: `frontend/app/_components/graph/useGraphPointer.ts` `updateHover()` — `externalFocusedNodeIdRef.current` 확인 로직

**검증 기준**

- 문서 처리 중 노드를 선택한 상태에서 3초 이상 대기해도 그래프 하이라이트가 유지된다.
- 문서 처리 완료로 `graphSignature`가 바뀌어도 선택된 노드의 이펙트가 사라지지 않는다.
- 노드 선택을 해제(빈 영역 클릭)하면 이펙트가 정상적으로 사라진다.
