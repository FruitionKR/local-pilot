# 2026-07-25 AI·Pipeline 이슈

## 삭제 workspace의 진행 중 pipeline 중단

### 현재 backend 보호

- backend 처리 큐는 삭제 workspace 또는 삭제 문서의 새 pipeline 요청을 시작하지 않는다.
- backend status·heartbeat callback은 삭제 workspace 또는 삭제 문서를 `404`로 처리한다.

### 남은 문제

- 이미 실행 중인 llmPipeline 작업은 workspace가 삭제된 사실을 알지 못한다.
- llmPipeline이 backend callback 전에 DB에 직접 쓰는 Wiki 산출물은 workspace 삭제 후에도 반영될 수 있다.
- workspace 복구 시 삭제 중 완료된 산출물을 유지할지 폐기할지 정책이 필요하다.

### 필요한 작업

- pipeline 실행 중 workspace 활성 상태를 확인할 경계를 정의한다.
- 취소 신호 또는 terminal 상태 계약을 추가한다.
- 직접 DB 쓰기를 backend 완료 handler 소유로 이전하거나 삭제 workspace write guard를 추가한다.
- 삭제와 pipeline 완료가 경합하는 통합 테스트를 추가한다.

### 관련 문서와 확인 위치

- `docs/spec/pipeline-db-ownership.md` — pipeline 직접쓰기와 backend 완료 handler 계획
- `backend/src/main/java/fruition/document/service/DocumentService.java` — `doRequestProcessing`, `updateStatus`, `applyPipelineEvent`
- `backend/src/main/java/fruition/document/repository/DocumentRepository.java` — `findByIdInActiveWorkspace`
