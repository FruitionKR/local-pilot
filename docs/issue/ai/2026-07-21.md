## 3. Agent turn production 연동 후속 작업

Markdown Agent router, `replace`·`insert_after`, Markdown 생성, source-range 편집, 구조 경계와 출력 계약 검증은 이미 구현되어 있다. 관련 구현 완료 기록은 `docs/backlog/issue-2026-07-21.md`의 `AI — Markdown 편집 router와 생성 계약 보강`에 보관돼 있다. 아래 항목만 production 연동 전에 추가로 처리한다.

### 3.1 target 생략 전체 편집의 후행 빈 줄 계산 통일

- `HandleAgentTurnUseCase._whole_document_target()`은 `len(markdown.splitlines())`로 마지막 line을 계산한다.
- `GenerateMarkdownEditUseCase`와 `markdown_line_count()`는 정규식 split을 사용해 문서 끝 개행 뒤의 빈 line도 계산한다.
- 따라서 후행 개행이 있는 Markdown에서 target을 생략하면 `whole_document` target이 실제 line 수보다 짧아져 `whole_document target must cover the entire Markdown document` 400 오류가 발생할 수 있다.
- `_whole_document_target()`도 `markdown_line_count()`를 사용하고, 후행 `\n`·`\r\n`·빈 문서 fixture를 Agent use-case와 HTTP route 테스트에 추가한다.

### 3.2 예상하지 못한 500 응답의 내부 정보 차단

- `llmPipeline/app/modules/agent/interfaces/http/routes.py`는 generic exception을 `detail=str(exc)`로 반환한다.
- Markdown 계약 오류는 이미 안전한 code/message로 변환하지만, 그 밖의 LLM client·DB·network 예외는 endpoint, 내부 경로 또는 provider 응답을 노출할 수 있다.
- 상세 오류는 server log와 correlation 정보에만 기록하고, HTTP 500에는 안정된 generic message만 반환한다.
- 내부 exception 문자열이 응답에 포함되지 않는 route 회귀 테스트를 추가한다.

### 3.3 Spring 연동 후 실제 계약 검증

- Backend public endpoint 작업은 `docs/issue/backend/2026-07-21.md`의 `4. Markdown Agent turn public endpoint 부재`를 따른다.
- Spring이 변환한 실제 payload로 `chat_answer`, `markdown_edit`, `markdown_create`, `clarify`, `reject` 다섯 action을 확인한다.
- 편집은 selection/current section/whole document와 `replace`/`insert_after` target echo를 검증한다.
- 생성은 backend가 공급한 최근 대화 요약과 reference context가 `MarkdownCreateRequest`까지 전달되는지 확인한다.
- 422 세 종류와 generic 500이 Spring을 거쳐도 code/message 계약을 유지하는지 확인한다.
- 로컬 또는 배포 target model에서 요약, 번역, cleanup, 표, checklist, 회의록 fixture를 각 3회 실행하고 action 정확도, 계약 통과율과 p95 latency를 기록한다.

### 완료 조건

- target을 생략한 후행 개행 문서가 올바른 `whole_document` 범위로 편집된다.
- 예상하지 못한 500 응답에 내부 exception 문자열이 노출되지 않는다.
- Spring public endpoint를 통한 다섯 action과 주요 오류의 E2E 계약 테스트가 통과한다.
- 대화 기반 생성 결과가 실제 session context를 사용하며, 대표 편집 fixture 반복 결과와 latency가 문서화된다.
