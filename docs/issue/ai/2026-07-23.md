# 2026-07-23 AI/Pipeline 이슈

## 활성 wiki-schema를 agent turn에 주입 (stream4 스키마)

llmPipeline `wiki_schema` 모듈은 완성돼 있으나, agent 편집/생성 턴에 **활성 스키마가 반영되지 않는다**. `build_markdown_editor()`가 `schema_prompt_provider` 없이 생성되어 기본값(`lambda: ""`)으로 동작한다. 스킬(스키마)을 제품화하려면 활성 스키마를 프롬프트로 주입하는 provider 연결이 필요하다.

프론트는 스킬 작성→preview→activate 임시 UI를 목업으로 구현했고(`frontend/app/_components/schema/`), Backend Java 프록시는 별도 이슈로 정리했다(`docs/issue/backend/2026-07-23.md`의 `wiki-schema Java 프록시 신규`).

### 필요한 작업

- `build_markdown_editor()`에 `schema_prompt_provider`를 주입한다.
- provider는 현재 workspace/user의 활성 스키마(`get_active_schema` / `build_active_schema_prompt`)를 조회해 프롬프트 조각으로 반환한다.
- 편집(`edit`)·생성(`create`)·질의(`query`) 등 feature별 조각(`SchemaFragments`)을 해당 턴 유형에 맞게 반영한다.

### 확인 위치

- 주입 지점: `llmPipeline/app/modules/agent/interfaces/http/dependencies.py`의 `build_markdown_editor()`
- 활성 스키마 조회/프롬프트: `llmPipeline/app/modules/wiki_schema/application/get_active_schema.py`, `.../application/build_active_schema_prompt.py`, `.../infrastructure/active_schema_prompt.py`
- 스키마 조각 정의: `llmPipeline/app/modules/wiki_schema/domain/entities.py`의 `SchemaFragments`, `SchemaFeature`
- 프론트 화면(목업): `frontend/app/_components/schema/`, `frontend/app/_lib/api/schema.ts`

### 완료 조건

- 활성 스키마가 있을 때 agent 편집/생성 턴 프롬프트에 해당 조각이 반영된다.
- 활성 스키마가 없으면 기존과 동일하게 빈 프롬프트로 동작한다(회귀 없음).
